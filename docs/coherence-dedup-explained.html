01为什么需要去重

GO 术语是层级传播的：一个基因被注释到某个具体术语，它就自动属于该术语的所有祖先。 于是「核糖体生物发生」和「rRNA 加工」和「核仁」在成员集合上高度重叠 —— 它们是同一个信号的多个名字。

按连贯性 z 值排名前 14 的术语（z 越负 = 在 DR–DL 空间里越紧密）

zsource术语成员簇代表?

注意「簇」这一列：前 14 名只落在 7 个簇里。第 1、2、3、5、11 名 （核糖体生物发生 / rRNA 加工 / 核糖核蛋白复合物生物发生 / rRNA 代谢 / 核仁） 全部属于同一个簇 all:0。 不做去重，你的「最连贯复合物」排行榜前五名是同一条。

02判据：成员集合的 Jaccard 相似度

每个术语被表示成它的被打分基因集合（scored_member_names， 即 DR < −0.3 的那批基因 —— 正是 z 值真正计算所依据的集合）。 两个术语的相似度用 Jaccard 指数：

J(A, B) = |A ∩ B| / |A ∪ B|

分母是并集。这一点是 2026-09 才改对的，之前踩过一个很大的坑 —— 看下面的三组真实案例。

真实案例

Jaccard  |A∩B| / |A∪B|0.750
包含系数  |A∩B| / min(|A|,|B|) 旧方法，已弃用1.000

弃用 min() 的原因：只要 A ⊆ B，|A∩B| / min(|A|,|B|) 恒等于 1.0。 而 GO 传播让「包含」无处不在 —— 每个子术语都被它所有祖先包含。 结果：相似度图被瞬间连成一片，2,097 个术语塌成 2 个簇。 Jaccard 仍然给真实的嵌套关系高分（子术语覆盖父术语大部分时），但不再单凭「包含」就判满分。

算法上有两个实现细节

1. 候选对用倒排索引，不做 O(n²) 全扫。 先建 gene → 术语列表，只在共享 ≥1 个基因的术语之间生成候选对。

实测：1,706 组的表上产生 555,784 对，全扫是 1,454,365 对 —— 只省 2.6 倍。 因为 GO 传播后每个基因挂载的术语数 k 很大，对数 ≈ Σgene C(k, 2)。 这是常数优化，不是渐近优化，但对当前规模够用。

2. 连通分量用 scipy 的 CSR 图 + connected_components （本质就是并查集），因此聚类是传递的：A~B 且 B~C ⟹ A 和 C 同簇， 哪怕 A 和 C 之间毫无相似性。这是本方法最重要的性质，也是最主要的代价。

04传递闭包的真实代价

上面 6 个术语里，GO:0180046（27 个成员）和 GO:0019637（111 个成员） 的直接相似度是 0.190，差得很远。但在完整的 2,097 行图里，它们之间存在这样一条路径：

直接相似度 J(起点, 终点) = 0.190   —   却并进了同一个簇

簇 all:15 最终包含 169 个术语，成员规模从 3 跨到 111。 每一步的相似度都在阈值以上（0.786 / 0.500 / 0.511 / 0.811）， 但两端说的是不同的事：一端是 GPI 锚定蛋白合成，另一端是所有有机磷代谢。

这就是为什么 Jaccard 的分母用并集只解决了一半问题。它防止了「单步包含」被误判， 但没有防止「多步漂移」。当前配置（阈值 0.5 + 传递闭包）的实际簇大小分布是： 153 个簇只有 1 个术语，136 个簇是 2 个术语， 但最大的几个簇分别吞掉了 169 / 108 / 60 / 44 / 37 个术语。 对那几个大簇，代表选取才是真正决定你看到什么的地方（见第 6 节）。

05DAG 谱系规则，为什么默认关掉

代码里有一条可选规则（dedup_merge_dag_lineage，配置中为 false）： 如果两个术语有 is_a / part_of 的祖先关系且共享 ≥1 个成员， 就判为冗余（不相交的兄弟术语永远不会被合并）。

用真实数据看这条规则会发生什么

为什么这会炸：GO 传播保证 —— 每个术语都和它所有的祖先共享成员。 所以「共享 ≥1 成员」这个保护条件在这里形同虚设；get_all_upper() 给出的是整个祖先集合而不是父节点；传递闭包一开，整张 DAG 链成一坨。

实测（记录在 config/analysis.yaml）：打开后 2,046 / 2,097 个术语落进同一个簇，而且调阈值几乎没用 —— 0.5 → 0.9 只把最大簇从 2,046 挪到 1,966。

它当年看起来无害，只是因为旧的包含系数已经先把所有嵌套对合并完了，掩盖了它的破坏性。
要重新启用它，前提是换一条规则：只合并单步父子（直接 parent/child）， 而不是合并整个祖先集合。

06每个簇选一个代表

簇建好之后，每簇挑一行当代表。默认排序键有四个，按优先级依次使用：

q_value ↑  →  median_pairwise_distance_z ↑ 越负越好  →  dag_depth ↓ 越深越特异  →  n_scored_members ↑ 越小越好

另外 dedup_force_representatives 里列出的 group_id 会无条件当选 （记为 forced），否则记为 auto。 下面是真实的簇 all:126，点按钮逐级看排序键如何起作用。

术语名称成员z qdepth

一个真实的坑：q 是第一排序键，而 q 不能跨 source 比较。 看排名第一的簇 all:0（核糖体那一坨）：代表是 nucleolus（z = −5.04）， 而不是 z 值好得多的 ribosome biogenesis（z = −7.78）。 原因是 q_value 是每个 source 内部独立做的 BH 校正 （nucleolus 来自 go_cc：q = 0.0135；ribosome biogenesis 来自 go_bp：q = 0.0222）， 两者不在同一个多重检验校正体系里，数值不可比。

对 pooled 作用域下跨 source 合并的簇，这意味着代表选择会被 「哪个 source 的术语更少、校正更宽松」影响。 想按纯连贯性选代表，得把 z 提到第一键。

07输出与作用域

两张 TSV，所有行都保留

文件内容怎么用
coherence_terms_deduplicated.tsv 2,097 行全量 + 新增列 审计：每行都标了它属于哪个簇、谁被选为代表
coherence_terms_representatives.tsv 477 行，只留 is_representative 的行 画图 / 写正文用这张

新增的 7 列：

redundancy_cluster · cluster_size · dag_depth · is_representative · representative_group_id · representative_name · representative_source

排序规则：先按「本簇最好的 z 值」排簇，簇内再按各术语的 z 排 —— 所以每个簇的代表总是排在它自己那一组的第一个。 输出前列表列 scored_member_names 会被 join 成逗号分隔字符串 （Parquet 里是真 list 列，为了 round-trip 不丢 dtype；TSV 是给人读的）。

作用域：pooled vs per_source

pooled（当前默认）：所有 source 合成一张图，同一个 GO 术语出现在两个 source 里会被合并。

真实案例 —— 簇 all:135：

source术语成员z q结果
go_macrocomplexGO:0032797 SMN complex 3−1.7640.0393 → 代表
go_ccGO:0032797 SMN complex 3−1.7640.0439 合并
go_ccGO:0034719 SMN-Sm protein complex 4−0.6590.385 合并

同一个 GO 术语、同一个成员集合、同一个 z 值，只因为来自不同 source 就有不同的 q （BH 校正是按 source 单独做的）。三条被并成一簇，代表是 q 最小的那条 —— 也就是 go_macrocomplex 那一份。这正是上面那个「q 跨 source 不可比」问题的具体表现。

per_source：每个 source 单独建图， 簇 id 带 {source}: 前缀保持全局唯一。 上例中 go_cc 的两条会自己成簇，go_macrocomplex 的不参与合并。

它做完之后你会做什么

自动选出的代表只是起点。完整簇成员全部导出，就是为了让你 （或让 dedup_force_representatives）手工改选 —— 因为 「哪个名字最好读、最该写进正文」是领域判断，不是排序键能解决的。 当前配置里这个列表是空的（0 forced representatives）。
